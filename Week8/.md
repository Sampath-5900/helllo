# Task 5 #

## Compare Cloud vs On-premise Costs ##

Option	Example specification	Upfront cost	Estimated 1-year cost	Estimated 3-year cost
Consumer desktop PC	Intel Core i5, 16 GB RAM, 512 GB SSD	AUD $1,099	AUD $1,099 plus electricity	AUD $1,099 plus electricity/maintenance
Azure Linux VM	D2s v5 style VM, 2 vCPU, 8 GB RAM	AUD $0 upfront	About AUD $1,250-$1,400 if left on continuously	About AUD $3,750-$4,200 if left on continuously

For comparison of cost, I made a similar mid-range virtual machine in the cloud to a desktop PC for the user. The desktop PC is more expensive up front, but requires no charges by the compute hour. The Azure VM is a more budget-friendly option, and it can be deployed rapidly, but can cost more if it is deployed and used for a year or three years. Cloud computing offers greater flexibility as resources can be resized, stopped, deleted and created as needed. But, on-premise hardware may be less expensive for long-term use and may afford physical control. If you need the lab for short-term use, testing, scaling or remote access, cloud is the better solution, if you need the lab for regular use, it is better to have a desktop PC refer to figure 3.

### Azure CLI Commands Used / To Record ###

az group create --name <RESOURCE-GROUP> --location <REGION>
az vm create --resource-group <RESOURCE-GROUP> --name my-vm --image Ubuntu2204 --admin-username azureuser --generate-ssh-keys --public-ip-sku Standard
az vm extension set --resource-group <RESOURCE-GROUP> --vm-name my-vm --name customScript --publisher Microsoft.Azure.Extensions --version 2.1 --settings '{"fileUris":["https://raw.githubusercontent.com/MicrosoftDocs/mslearn-welcome-to-azure/master/configure-nginx.sh"],"commandToExecute":"./configure-nginx.sh"}'
ssh -l azureuser <PUBLIC-IP-ADDRESS>
sudo nano /var/www/html/index.html

The optional storage blob activity illustrates how Azure stores files in containers and manages the visibility of the files (private or anonymous). The storage account configuration will need to be altered before the container can be made public if anonymous access is disabled. The resource lock task describes what protection settings are - delete lock means that data may not be deleted, and read-only lock means that data may not be deleted or modified refer figure 4-5. These controls are beneficial in the real environment as they help to minimize the potential for unintentional changes to valuable cloud resources.
	Read Only Lock Vs Delete Lock
Lock Type	Allows	Blocks	Best For
Read-only lock	View only	Changes and deletion	Protecting resources from any modification
Delete lock	View and edit	Deletion only	Preventing accidental deletion
